# 常见问题与排查

排查顺序永远是：**先 `sfs doctor`**。它会一次性把服务、显卡、补丁、模型、磁盘全查一遍，
并且对每一项给出下一步该做什么。

```bash
sfs doctor
sfs doctor --package-root D:\Works\ACE-Step-1.5-portable
```

---

## 服务相关

### 报「连不上 http://127.0.0.1:8001」

先确认服务真的起来了。

如果你用的是双击启动，`启动.bat` 会自己把引擎带起来并等它就绪，控制台会报进度。
如果它说没找到便携包，加上 `--engine-root D:\你的目录` 再试。

要单独起引擎，用便携包根目录下那份修正版 `启动引擎.bat`，**不要用官方的
`start_api_server.bat`**（原因见下）。

如果服务在别的机器或别的端口：

```bash
sfs doctor --base-url http://192.168.1.10:8001
sfs make --base-url http://192.168.1.10:8001 ...
```

### 端口能连上，但 /health 不正常

服务可能还在初始化模型。冷启动要等 1 到 2 分钟（planner 初始化实测 138 秒）。
持续不正常就看服务端日志。

这种情况**不要反复双击启动**：端口已被监听说明有人正在起，重复启动只会让两个进程
抢同一个端口。`启动.bat` 已经处理了这一点 —— 它会识别出「正在初始化」并只等不拉。

## 启动脚本相关

### 双击 `启动.bat` 后说要等很久

首次运行要下约 10GB 模型，可能十几分钟；之后每次冷启动约 1 分钟。控制台每 15 秒报
一次进度。

**等不及可以直接关窗口**，但要知道引擎也会跟着停 —— 下次双击还是要重新等。想彻底
免掉这个等待，就用便携包根目录的 `启动引擎.bat` 先把引擎单独开着（它会占着一个窗口），
之后 `启动.bat` 检测到引擎已在跑就直接进界面。

### 官方 `start_api_server.bat` 起不来

已知问题，不是你的环境坏了。那个脚本判断的目录名是 `python_embedded`，
而便携包实际目录叫 `python_embeded`（**少一个 `n`**），判断永远不成立，
于是它掉进 uv 分支去用 `.venv` —— 那是个没装 torch 的空壳。

用便携包根目录下的 `启动引擎.bat`（修正版），或者直接双击项目的 `启动.bat`
让它代管引擎。

### 报 `ModuleNotFoundError: No module named 'torch'`

同上：挑错了 Python。便携包里有两套：

| 路径 | 能不能用 |
|---|---|
| `<便携包>\python_embeded\python.exe` | **只能用这个**（3.11.9 ＋ torch 2.7.1+cu128） |
| `<便携包>\.venv\Scripts\python.exe` | 用不了（3.12.0，没有 torch） |

`sfs doctor` 和 `启动.bat` 判的都是前者。

## Windows 相关

### diffusers 导入失败，报 WinError 5 / PermissionError

triton 那个坑，见 [01-Windows部署实录.md](01-Windows部署实录.md) 第二节。一条命令解决：

```bash
python tools/patch_windows_triton.py --package-root D:\Works\ACE-Step-1.5-portable
```

### 内存 / 显存不够，跑到一半崩了

先看 `sfs doctor` 的显存占用那项。实测 DiT 与 LM 同时在卡上要 14.2 GB / 16 GB。

- 把 `--batch` 保持为 1
- 关掉别的推理服务
- 关掉浏览器里的 3D 页面
- 换更小的 LM 型号

### 控制台中文乱码

本项目的 CLI 已经把标准输出切成 UTF-8 并对无法编码的字符降级替换。
如果你是直接调用 `client.py`，记得自己处理编码：

```python
import sys
sys.stdout.reconfigure(encoding="utf-8", errors="replace")
```

## 歌词相关

### 体检报「没有检测到结构标签」

歌词没有 `[Verse]` / `[Chorus]` 这类标签。加上标签模型才知道段落边界，
成品结构会明显更清楚：

```text
[Verse 1]
主歌内容

[Chorus]
副歌内容
```

支持中文标签（`【主歌】`、`【副歌】`）和英文标签。

### 体检报「行太长」

按显示宽度算，一个汉字算 2 列。经验阈值是单行超过 40 列偏长、超过 64 列基本唱不顺。

这是统计出来的常见区间，不是硬性规定。想保留长句也可以加 `--force` 跳过。

### 体检报「副歌内容各不相同」

有多段副歌但每段唱词都不一样。重复副歌是让人记住一首歌的主要手段。
如果不是刻意做「副歌递进」，建议统一唱词。想强行生成加 `--yes`。

### 体检有警告，怎么继续

```bash
sfs make ... --yes      # 有警告也继续
sfs make ... --force    # 有错误也继续
```

## 出歌效果

### 听起来不像中文歌

- 确认 `--lang zh`（用 `--style` 时默认就是 zh）
- 歌词里汉字占比要够。`sfs check` 会报汉字占比
- 风格描述也用中文写，效果更一致

### 结构很平，像一段加长版

- 确认歌词有 `[Chorus]`。没有副歌的歌词，成品容易听起来像一段长的前奏
- 保留 `thinking=True`（默认开）。关掉 planner 思考会快，但曲式结构会变差

### 出歌速度慢

分两段看，别混在一起：

- **启动那一段**：双击后要先花约 1 分钟把模型载入显存（日志里会走完
  `Initializing models` 到 `All models initialized successfully`）。
  首次运行还要下约 10GB 模型，更久。
- **出歌那一段**：模型在显存里之后是 10 到 30 秒。每次冷启动后的第一首最慢
  （120 秒人声实测 30.7 秒），之后落到 10 到 15 秒。

本项目故意把模型载入放在启动时，而不是第一次出歌时 —— 后者会让界面上的第一次
出歌干等一两分钟，看着像卡住。中途别重启服务。

## 复现与追溯

### 想复现某一版

每次生成都会在音频旁写一个同名 `.json`，里面记了完整的请求参数、seed、
风格描述、歌词原文，以及模型补出来的元数据。照着里面的 `reproduce` 字段跑就行。

注意：**固定 seed 但改了风格描述或歌词，结果会完全不同。** 三者都要一致。

### 想知道当时模型判了多快

`sfs songs` 会列出输出目录里的歌，附上 BPM 与调式。

## 其他

### 数据会传出去吗

不会。整条链路是本机的，客户端只连你指定的地址，默认 `127.0.0.1`。

### 能不能批量出歌

可以循环调用：

```bash
for f in lyrics/*.txt; do
  sfs make --style folk --lyrics-file "$f" -o "$(basename "$f" .txt).mp3" -y
done
```

### 上游接口变了怎么办

字段以源码 `acestep/api_server.py` 为准。本项目只依赖三个端点
（`/health`、`/release_task`、`/query_result`）和三个状态位（0 排队、1 成功、2 失败），
这几样是最稳定的部分。
